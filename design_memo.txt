Hospital Intake System — Design Memo

A tree fits the doctor reporting structure because management relationships form a hierarchy. The root represents the lead doctor, and each child represents a direct report. This assignment uses a binary tree, so a doctor can have at most two direct reports. A real hospital could need a more general tree with additional children. This is not a binary search tree: doctors are placed under a specified manager rather than sorted by name. The insert method searches for the parent and rejects invalid sides, missing parents, duplicate names, and occupied positions without replacing existing reports.

Preorder visits a manager before their reports. An engineer could use it to display an organization chart or distribute instructions from leadership downward. Inorder visits the left subtree, then the current doctor, then the right subtree. It gives a consistent structural listing here, but it does not alphabetize the doctors. In a binary search tree, inorder would instead produce sorted values. Postorder processes reports before their manager, which could support collecting departmental summaries before generating a management summary. Each traversal uses recursion and returns a list.

The emergency queue uses a custom min-heap so the lowest urgency number stays at the root. Insertion moves a patient upward, while removal moves the last patient to the root and restores order downward. These operations take O(log n) time, and peek takes O(1). This supports changing intake without sorting the entire queue repeatedly. The exercise uses urgency levels 1 through 10. Equal urgency patients have no guaranteed arrival order; a production system could add arrival timestamps and support reassessment. Empty queues raise clear exceptions.
